# 攻略文本抽取 Prompt v0.1（附加E 粘贴游记 → 候选条目）

> 负责人：技术1 ｜ 版本：v0.1（2026-10-21，Week 2）｜ 服务接口：`extract_guide`（见 [02-Agent接口契约 §3.6](../02-Agent接口契约.md)）
> 底层模型：DeepSeek chat（同 generate）｜ API 参数：temperature=0.5, max_tokens=2500, response_format=json_object

---

## 1. 接口定位

用户**主动粘贴**的游记正文（小红书/马蜂窝/公众号/朋友发的 Word 文档），LLM 提取结构化候选条目。红线：不爬虫、不读链接、不读图片（多模态图片识别列为 future work，报告里可写"粘贴文本 + 上传截图"是可选扩展）。

用户体验：粘贴 → 等 3-10 秒 → 看到候选列表（每条附原文摘录溯源）→ 勾选想导入的 → 确认后正式加入行程。

## 2. API 参数

```jsonc
{
  "model": "deepseek-chat",
  "temperature": 0.5,
  "max_tokens": 2500,
  "response_format": { "type": "json_object" },
  "stop": [],
  "top_p": 0.9
}
```

## 3. 变量表

| 变量 | 说明 |
|---|---|
| `{{text}}` | 用户粘贴的文本，截断上限 8000 字（超出部分丢弃，前端提示"文本过长已截取前 8000 字"） |
| `{{city}}` | 目标城市（约束里来），过滤无关条目；若文本跨城市，只取目标城市相关 |

## 4. System Prompt

```text
你是游记攻略解析器。用户会粘贴一段游记正文，你的任务是从中提取结构化的候选行程条目。你只输出一个 JSON 对象，符合下方骨架。

# 提取规则
1. 只提取在 {{city}} 范围内的景点/餐厅/酒店/交通。其他城市的条目忽略
2. 对每个提取的条目，必须同时提供 excerpt（原文摘录），让用户能溯源核对。摘录要短——截取包含关键信息的 1-2 句话，不要整段复制
3. 识别文本中提到的"第X天""Day X""上午""下午""晚上"等时间线索，填入 suggested_day_index 和 time_slot。没有明确时间线索时这两个字段填 null
4. 价格：文本里提到了费用（如"门票 55 元""人均 80"）就填 amount（注意是总金额还是人均——如果文本写"人均 80"，按估算全组金额填入并在 note 标注）；没提到就填 null（不要编造）
5. POI 名称要精确——用户写"宽窄巷子"就是"宽窄巷子"，不要扩成"成都宽窄巷子历史文化区"。精确匹配的目的是让后端去地图 API 校验存在性
6. 类型 type 只能是：poi（景点/景区/公园/博物馆/寺庙/文化街区）、meal（餐厅/小吃店/咖啡馆/酒吧）、hotel（酒店/民宿/客栈）、transport（市内交通方式，如地铁/打车/公交路线）、free_time（自由活动/逛街/看演出）
7. 文本里提到的负面信息（如"这家店已歇业""XX 正在维修"）要特别注意——如果能提取出 POI 就提取但加 warning；如果完全无法确认就跳过
8. 不做跨城市交通的大交通（机票/高铁）提取，那是附加 F 的范畴

# 输出骨架（纯 JSON，一字段不多、一字段不少）
{
  "candidates": [
    {
      "candidate_id": "cand-1",
      "title": string (POI 精确名称),
      "type": "poi" | "meal" | "hotel" | "transport" | "free_time" | null,
      "suggested_day_index": integer | null (1-based, 从文本的"第X天"推断),
      "time_slot": {
        "start": string | null (HH:MM),
        "end": string | null (HH:MM)
      } | null,
      "location": {
        "name": string | null (等于 title),
        "address": null,
        "lng": null,
        "lat": null,
        "poi_id": null,
        "poi_source": "llm"    // 所有候选都是 LLM 提取的占位，后端会用地图 API 校验后回填
      },
      "cost": {
        "amount": number | null (总金额估算，不要编造),
        "currency": "CNY",
        "price_type": "estimate",
        "source": "llm",
        "note": string | null (如"原文提到人均80，4人估算320"或"原文未提及价格")
      },
      "note": string | null (补充说明，如"原文提到需预约""原文提到周一闭馆"),
      "excerpt": string (必须提供！原文摘录，1-2句，不超过150字),
      "selected": false
    }
  ],
  "warnings": [
    string (如"文本中提到『XX餐厅已歇业』，该条目仅供参考")
  ]
}

# 额外注意
- 如果文本中完全没有可提取的候选条目，返回 { "candidates": [], "warnings": ["未在文本中识别到 {{city}} 相关的可用条目"] }
- 标题去重：同一 POI 在文本中多次出现，合并为一个条目，excerpt 取最完整的那次
- 文本中的 emoji、特殊符号、图片描述（如"[图片]""配图一张"）自动忽略
```

## 6. 测试用例

### 用例 1：正常小红书风格游记

**输入**

```
用户粘贴：
"成都3天深度游！Day1 宽窄巷子人好多，早上9点去刚好，免费！然后去人民公园喝茶，下午逛了四川博物院（免费，周一闭馆注意！）。晚上吃的陈麻婆豆腐，人均80，辣到怀疑人生，不能吃辣的慎入！
Day2 熊猫基地一定要早去，8点开园，门票55。下午春熙路太古里逛街，晚上建设路小吃街，蛋烘糕必吃！"
目标城市：成都
```

**预期输出要点**

- candidates 数量 ≥ 6（宽窄巷子、人民公园、四川博物院、陈麻婆豆腐、熊猫基地、春熙路/太古里、建设路小吃街）
- 每个条目有 excerpt 且来自原文
- 四川博物院 note 含"周一闭馆"
- 陈麻婆豆腐 cost.note 含"人均80"
- 所有 location.poi_source = "llm"
- warnings 为空数组

### 用例 2：跨城市文本 + 负面信息

**输入**

```
用户粘贴：
"国庆走了一圈：第一天上海外滩，第二天苏州拙政园，第三天回成都打卡建设路小吃街，结果到了发现那家网红冰粉店装修停业了！只好去旁边的钟水饺，还不错。"
目标城市：成都
```

**预期输出要点**

- 只提取建设路小吃街（网红冰粉店停业→跳过或加 warning）+ 钟水饺
- warnings 含"原文提到网红冰粉店装修停业"
- 上海外滩、苏州拙政园因跨城市被忽略

### 用例 3：无有效内容

**输入**

```
用户粘贴："成都好棒！下次还来！"
目标城市：成都
```

**预期输出**

```json
{
  "candidates": [],
  "warnings": ["未在文本中识别到成都相关的可用条目"]
}
```

## 7. 已知风险与应对

| 风险 | 应对 |
|---|---|
| 文本含 JSON 特殊字符（`"`/`\`/换行）导致 DeepSeek 输出 JSON 非法 | L0 清洗：程序剥离 markdown 围栏、修复尾随逗号、转义未处理的引号；v0.2 视实测在 Prompt 中强化 |
| 超长文本截断导致条目残缺 | 8000 字硬截断 + 前端提示；DeepSeek 可能在截断处输出半截 JSON，L0/L1 校验失败进修复循环 |
| 同一 POI 被 LLM 拆成两个条目 | System Prompt 提了去重规则；L2 可加 location.name 精确匹配去重（后端做） |
| 价格单位混乱（分/元/美元） | 红线：不编造价格，识别不到就填 null；excerpt 溯源让用户自己判断 |
| 多模态图片识别 | 本期不做，报告里写"future work：用户上传游记截图 → 多模态 VL 模型 OCR 后再抽" |

## 8. 调优指标（Week 3 验收时）

- 候选提取召回率 ≥ 80%（人工标注后比对）
- excerpt 溯源准确率 ≥ 95%
- L1 JSON 一次通过率 ≥ 90%
- 用户勾选导入后的 POI 存在性校验通过率 ≥ 70%（剩下 30% 是 LLM 编造的近似名，标注"待核实"）
